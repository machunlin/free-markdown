# FreeMarkdown Security Guidelines

> Last updated: 2026-09-03

## Threat Model

FreeMarkdown is a **local file editor**. It processes files from the user's filesystem and renders them in a WebView. Primary threats:

1. **Local file access:** Malicious Markdown files or path traversal attacks that read files the user didn't authorize
2. **Cross-site scripting (XSS):** Malicious Markdown/HTML that executes JavaScript in the WebView
3. **Capability abuse:** Overly permissive Tauri capabilities granting unnecessary OS access
4. **Data exfiltration:** Sending file contents over network
5. **Code execution:** Arbitrary command execution via shell injection or similar vectors

## Security Architecture

### Default-Deny Philosophy

- No filesystem access for the WebView by default
- No shell access
- No network access by default
- No raw HTML in Markdown by default
- All file access goes through audited Rust commands with path validation

### Tauri Capabilities

Tauri 2 capability files in `src-tauri/capabilities/` define permissions. Only the minimum required permissions are granted.

**Default capability (main window):**

```json
{
  "identifier": "default",
  "windows": ["main"],
  "permissions": [
    "core:default",
    "dialog:allow-open",
    "dialog:allow-save",
    "dialog:allow-message",
    "dialog:allow-confirm",
    "core:window:allow-minimize",
    "core:window:allow-maximize",
    "core:window:allow-close",
    "core:window:allow-set-title",
    "core:window:allow-set-fullscreen",
    "core:window:allow-start-dragging",
    "core:event:allow-listen",
    "core:event:allow-emit",
    "core:app:allow-version",
    "core:app:allow-name"
  ]
}
```

**Explicitly NOT granted:**
- `fs:default` or any `fs:allow-*` — file access only through custom commands
- `shell:allow-execute` — no shell access
- `shell:allow-open` is not granted globally; use explicit `opn` crate calls from Rust after URL validation
- `http:default` — no HTTP client access from WebView
- `core:webview:allow-set-webview-focus` — not needed

### Content Security Policy

A restrictive CSP is set in `tauri.conf.json`:

```
default-src 'self';
script-src 'self';
style-src 'self' 'unsafe-inline';
img-src 'self' data: blob: https:;
font-src 'self' data:;
connect-src 'self' ipc: http://ipc.localhost;
media-src 'self' data: blob:;
frame-src 'none';
object-src 'none';
base-uri 'none';
form-action 'none';
frame-ancestors 'none';
```

Notes:
- `'unsafe-inline'` for styles is required for Tailwind and markdown preview styles.
- `https:` for images allows loading remote images; user can disable this in settings.
- No `script-src 'unsafe-inline'` or `'unsafe-eval'` — no inline JavaScript.

## File System Security

### Path Validation

Every path from frontend is validated in Rust before any I/O:

1. Path must be absolute (no relative paths like `../../etc/passwd`)
2. Path is canonicalized (resolves symlinks and `..` components)
3. Path must exist (for read operations) or parent must exist (for write)
4. Null bytes in paths are rejected
5. When a workspace folder is opened, paths must be within that folder (TBD for V0.5)

```rust
pub fn validate_path(path_str: &str) -> Result<PathBuf, AppError> {
    if path_str.contains('\0') {
        return Err(AppError::InvalidPath("Null byte in path".to_string()));
    }

    let path = Path::new(path_str);
    if !path.is_absolute() {
        return Err(AppError::InvalidPath(
            "Relative paths are not allowed".to_string()
        ));
    }

    let canonical = path.canonicalize().map_err(|e| {
        AppError::InvalidPath(format!("Cannot resolve path: {}", e))
    })?;

    Ok(canonical)
}
```

### File Access Model

Files become accessible only through explicit user action:
- User selects files via native open dialog
- User drops files onto the window/dock icon
- User opens a folder (then all files within are accessible)

There is NO global filesystem access from the WebView.

### File Writing Security

- Write operations only overwrite existing files or create files at user-specified paths
- Auto-save only writes to already-opened files (never creates new files without user action)
- Files are written atomically (write to temp file, then rename) to prevent corruption on crash

## Markdown/HTML Security

### HTML Sanitization

All HTML generated by markdown-it passes through DOMPurify before DOM injection:

```ts
DOMPurify.sanitize(html, {
  FORBID_TAGS: ['script', 'iframe', 'form', 'object', 'embed', 'link', 'base'],
  FORBID_ATTR: ['onerror', 'onload', 'onclick', 'onmouseover', 'onfocus', 'onblur', 'onchange', 'onsubmit'],
  ALLOW_DATA_ATTR: false,
  ADD_TAGS: ['math', 'semantics', 'mrow', 'mi', 'mo', 'mn', 'msup', 'msub', 'mfrac', 'msqrt', 'mroot', 'mover', 'munder', 'mtable', 'mtr', 'mtd', 'mlabeledtr', 'annotation'],
  ADD_ATTR: ['target', 'rel', 'aria-label', 'aria-hidden', 'role'],
});
```

### Raw HTML Disabled by Default

markdown-it is initialized with `html: false`. If users enable raw HTML in settings, DOMPurify still filters dangerous content.

### External Links

All `http://` and `https://` links open in the system default browser via the Tauri shell API (called from Rust after validation). They never navigate the WebView.

```rust
#[tauri::command]
pub fn open_external(url: String) -> Result<(), AppError> {
    let parsed = url::Url::parse(&url)
        .map_err(|_| AppError::InvalidInput("Invalid URL".to_string()))?;

    if parsed.scheme() != "http" && parsed.scheme() != "https" {
        return Err(AppError::InvalidInput(
            "Only http/https URLs can be opened externally".to_string()
        ));
    }

    open::that(parsed.as_str())?;
    Ok(())
}
```

## Encoding Security

- Encoding detection returns confidence levels; low confidence triggers user prompt (no silent decoding errors)
- Files are always processed as bytes first, then decoded; never assumed to be UTF-8
- Encoding labels from frontend are validated against known encoding list (arbitrary encoding names rejected)

## Network Access

FreeMarkdown is an **offline-first** application:
- All assets (fonts, KaTeX CSS/fonts, Mermaid, Shiki grammars) are bundled locally
- No analytics, no telemetry, no crash reporting (V0.1-V1.0)
- Image loading from HTTP URLs is allowed (user setting), but no other network access
- Update checking (if added in V2.0) will be opt-in only

## Dependency Security

### npm Dependencies

- `pnpm audit` is run regularly
- Only well-known, actively maintained packages are added
- Lockfile (`pnpm-lock.yaml`) is committed for reproducible builds
- Critical/high vulnerabilities block releases

### Cargo Dependencies

- `cargo audit` is run regularly
- `cargo deny` checks for duplicate dependencies, banned crates, and license issues
- `unsafe` code in dependencies is reviewed
- Application code uses `#![forbid(unsafe_code)]` where possible

## Data Privacy

- Zero data collection
- Zero telemetry
- Zero outbound network requests by default
- Recent files list stored locally only (in app config directory)
- Settings stored locally only
- File contents never leave the user's machine unless the user explicitly exports/shares

## Security Review Checklist

Before merging any code that affects security:

### Command additions
- [ ] Command validates all input parameters (paths, lengths, ranges)
- [ ] Paths are canonicalized and validated
- [ ] Return type is `Result<T, AppError>` with appropriate error variants
- [ ] No sensitive data in error messages that could leak filesystem info
- [ ] Async I/O used (no blocking)
- [ ] Capability file NOT modified to add blanket fs/shell permissions

### Frontend additions
- [ ] No `dangerouslySetInnerHTML` without DOMPurify
- [ ] No `eval()`, `new Function()`, or dynamic code execution
- [ ] No `javascript:` URLs
- [ ] External links have `target="_blank" rel="noopener noreferrer"` and go through open_external command
- [ ] DOMPurify configuration reviewed if modified
- [ ] No new scripts loaded from CDN in production

### Configuration changes
- [ ] CSP not weakened
- [ ] No new permissions added to capabilities without justification
- [ ] New dependencies checked against known vulnerabilities
- [ ] Tauri version checked for known issues

### Testing
- [ ] Path traversal tests added (`../../../etc/passwd`, null bytes, etc.)
- [ ] XSS payload tests for markdown preview
- [ ] Invalid encoding tests
- [ ] Large file handling (memory exhaustion)

## Reporting Vulnerabilities

Users can report security vulnerabilities via GitHub issues (marked as security) or directly to the maintainers. There is no bug bounty program, but reports will be responded to promptly.
